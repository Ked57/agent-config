## Findings and proposed repairs

### F1 · Seven automatic routes target explicit-only skills

`policy/routing.md` automatically selects `grill-me`, `grill-with-docs`, `implement`,
`to-spec`, `to-tickets`, `wayfinder` and `improve-codebase-architecture`. Each has
`disable-model-invocation: true` and Codex metadata with `allow_implicit_invocation: false`.
A named route does not reverse that explicit invocation contract. The counts are seven
unique skills, across the vague-target, ticket, multi-session, foggy-effort and upkeep
routes.

Repair: keep these workflows explicit and move them into one manual registry; ordinary
matching may suggest them. Keep `tdd`, `diagnosing-bugs`, `codebase-design` and `grilling`
as automatic owners within their scopes. Alternatively, deliberately change the seven
skills' metadata and record those vendor adaptations; do not leave both meanings active.
Add an invariant test that automatic targets permit automatic invocation.

Sources: `policy/routing.md:17–23`, each named skill's frontmatter and `agents/openai.yaml`,
`skills/writing-for-agents/SKILL-MECHANICS.md`. Invocation behaviour is also documented by
[Claude](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill) and
[Cursor](https://cursor.com/docs/skills#disabling-automatic-invocation).

### F2 · Sync preserves removed skill files, then check reports success

Confirmed in disposable source/home copies: remove `tdd/tests.md` from source, run
`sync --user`, then `check --user`; both exit 0 and the old guide remains installed.
Remove the whole `scaffold-exercises` source directory and repeat: both commands still
exit 0, while the deleted skill's `SKILL.md` remains discoverable.

The obsolete-entry branch in `planUser()` only removes owned, unchanged policy files or
marked agents. Skill entries become preserved/unmanaged. Project sync likewise does not
prune deleted skill paths. This is a cleanup/lifecycle defect; it does **not** mean the
currently vendored TDD guides are missing.

Repair: extend ownership-aware cleanup to obsolete skill paths, removing only files whose
prior installed hash still matches; preserve modifications and unrelated files. Test
removed support files, renamed skills, whole-skill deletion, local modifications and
idempotence. Define whether `check` should flag retained obsolete skill output instead of
silently treating it as healthy. Project cleanup needs its own trusted per-file hashes
before it can use the same safety rule.

Real local remnants found: `domain-modeling/CONTEXT-FORMAT.md` in both skill roots and the
two installed `impeccable` trees, absent from current source. All four were later deleted
with user approval. The installer's general lifecycle defect remains unmodified.

Source: `bin/agent-config.mjs`, `planUser()` obsolete-entry handling, `install()` and
`checkUser()`; reproduction results in `audit-evidence.json`.

### F3 · File detection and required quality routes disagree

Confirmed with a disposable project containing `src/example.mts`: the TypeScript policy
is installed, but generated verification globs cover only `**/*.ts` and `**/*.tsx`.
The file therefore has no TypeScript route. Ordinary `.test.ts`, `.spec.ts` and `.cy.ts`
changes outside domain/React scopes are excluded without a replacement test-file route.
`.cts` and root-level source are also outside current detection. React detection depends
on root dependencies, so package-only React declarations need a monorepo fixture.

`verify:full` and `build` can be discovered yet never required by a generated route.
`required: []` is also structurally valid when no candidate scripts exist. That may be an
honest missing gate, but it is not evidence that verification succeeded.

Repair: use matching detection/routing extensions, add test/config/tooling routes, include
package-local dependencies, and explicitly report uncovered paths or absent gates. Name
when the existing full release gate is required. Preserve the project-owned routing map
on sync; expose its stale/empty coverage rather than silently rewriting user decisions.

Source: `bin/agent-config.mjs`, source detection, `candidates`, `requiredChecks`, `config`
and `validateProjectConfig`; the `.mts` case was executed, other scope gaps follow from
these predicates and need regression fixtures before repair.

### F4 · Check validates command names, not executable script existence

Confirmed: initialise a project whose routing references `npm run typecheck` and
`npm run test`; remove those package scripts; `check --project` still exits 0. The
validator verifies that route keys exist in `commands`, not that those command strings
still resolve to an available task.

Repair: validate straightforward package-manager `run <script>` references against the
relevant package, and report commands requiring another task runner as unverified until
that runner's contract is checked. Keep execution of real checks separate from drift
validation. Add a stale-script test and a fresh-project source-completeness check.

Source: `validateProjectConfig()` and `check()`; executed before/after scenario in the
evidence. `check` should not be represented as having executed quality gates.

### F5 · Project-only Claude native skill discovery is not wired

A fresh project install writes all skills to `.agents/skills/` and creates `CLAUDE.md`,
but creates no `.claude/skills/` registrations. The user installer correctly creates both
roots. [Claude's documented project skill root](https://code.claude.com/docs/en/skills#choose-where-skills-load)
is `.claude/skills/`; a policy pointer to `.agents/` does not itself register native slash
commands. Cursor separately documents support for
[`.agents/skills/`](https://cursor.com/help/customization/skills).

Repair: add managed project registrations for Claude, or document/test an explicit
supported loading mechanism. Keep the canonical sources portable. Add a project-only
fixture with no global skills so personal installation cannot mask this gap.

Evidence: the fixture has `.agents/skills/tdd/SKILL.md` and no
`.claude/skills/tdd/SKILL.md`. This is a filesystem/documentation integration finding;
a fresh Claude process was not started, so actual native discovery is not claimed tested.

### F6 · Review router and leaf disagree, and WIP is omitted

The router supplies a base-branch merge-base default. `code-review/SKILL.md:19` instead
asks for a fixed point. Its mandatory `git diff <fixed-point>...HEAD` excludes staged and
unstaged changes even though the description advertises working-tree reviews.

Confirmed in this checkout: `git diff origin/main...HEAD --stat` is empty while
`git diff --numstat` reports the existing uncommitted Taste Skill changes. A WIP review
following the leaf command would reject an empty diff or inspect the wrong scope.

Repair: select one scope once: committed range, staged, unstaged, or combined WIP;
include untracked files deliberately for a combined review. Put the default and scope
resolution in one owner and test example commands against fixtures with each change type.

### F7 · Default test temp paths fail on this Mac

The targeted personal-install test fails under the current default temporary path because
`/var` is a system symlink rejected by installer path validation. The same suite passes
47/47 with `TMPDIR=/private/tmp`. This is test/environment portability friction, not a
reason to weaken the installer's symlink protection.

Repair: create fixtures under a canonical temporary root (`realpath` of the temp directory)
and retain explicit symlink rejection cases. Verify the default documented command on
macOS and the existing supported platforms. No checked-in CI configuration was found;
add CI for the existing verification command after the environment fix if CI enforcement
is intended.

### What each candidate does and where it comes from

All eight are unmodified vendored skills from
[`mattpocock/skills` at `49dd158`](https://github.com/mattpocock/skills/tree/49dd158d1076134a641b33efb035946536778336),

pack. Seven are explicit-only; `scaffold-exercises` permits model invocation through its
description. `teach` is additionally mentioned in the manual `ask-matt` router.

- **`scaffold-exercises` · upstream `skills/misc/scaffold-exercises`:** creates numbered course sections and exercises with problem/solution/explainer folders, README files and optional `main.ts`; it assumes the AI Hero-specific `pnpm ai-hero-cli internal lint` command and commits its work. Automatic description trigger, no policy or incoming skill reference; useful for that course-authoring convention.
- **`teach` · upstream `skills/productivity/teach`:** runs a persistent tutoring workspace with a learning mission, source material, HTML lessons, reference sheets and learning records; it uses retrieval practice and spaced/interleaved practice. Explicit-only, no policy route, referenced by `ask-matt`; useful if this bundle also supports personal learning.
- **`writing-fragments` · upstream `skills/in-progress/writing-fragments`:** interviews the author to collect raw claims, examples, observations and phrases into one Markdown file without imposing an outline. Explicit-only, no policy or incoming skill reference; useful for gathering material for articles and talks.
- **`writing-beats` · upstream `skills/in-progress/writing-beats`:** turns existing raw material into an article by offering two or three next narrative moves, writing the selected beat, then repeating while introducing concepts before relying on them. Explicit-only, no policy or incoming skill reference; useful for closely guided narrative composition.
- **`writing-shape` · upstream `skills/in-progress/writing-shape`:** shapes existing material into a separate article by choosing an opening and developing it paragraph by paragraph; it challenges the argument, ordering and format while keeping the source material unchanged. Explicit-only, no policy or incoming skill reference; overlaps `writing-beats`, with emphasis on article structure rather than branching narrative moves.
- **`chief-of-staff` · upstream `skills/in-progress/chief-of-staff`:** coordinates a long-running goal by delegating work to background agents and improving their environment; it proposes schedules when the harness supports them. Explicit-only, no policy or incoming skill reference; useful for deliberate orchestration rather than an ordinary coding task.
- **`claude-handoff` · upstream `skills/in-progress/claude-handoff`:** writes a temporary context summary and launches a named background Claude CLI agent with it via `claude --bg`. Explicit-only, no policy or incoming skill reference; useful for Claude CLI users. The separate `handoff` skill already writes a portable summary without requiring that launch mechanism.
- **`loop-me` · upstream `skills/in-progress/loop-me`:** interviews the user to identify recurring personal/work processes and write implementation-ready specs under `workflows/`, retaining context in `NOTES.md`. Explicit-only, no policy or incoming skill reference; it designs workflows and does not itself schedule or execute recurring jobs.

The upstream `in-progress` directory is provenance, not proof that a skill is obsolete or
broken. The three writing skills author prose; `writing-for-agents`, which remains
separate, governs instructions and policy documents.

## Routing and one-line policies

[The complete routing draft](audit-routing-proposal.md) distinguishes automatic owners,
child dependencies and all 31 explicit workflows. It gives each of the 71 current skills
a place without routing every ordinary change into a large multi-session process.

Useful compaction preserves one trigger and one testable meaning per line. Collapse
repeated ownership paragraphs; retain actual conditions and exceptions. The React Effect
and memoisation rules already contain valuable distinctions; reduce repeated wording
without turning them into unexplained prohibitions. Resolve project/global scope once
before following a pointer.

Highest-value additive policy lines, with detailed sources and scoped gates in
[audit-policy-proposals.md](audit-policy-proposals.md):

- TypeScript: validate untrusted data at the existing boundary parser before assigning a domain type.
- TypeScript: await or return promises, or attach a deliberate rejection handler to background work.
- TypeScript: narrow dictionary and positional array lookups as potentially missing.
- Vue: typecheck changed SFC scripts and templates with a `vue-tsc`-backed gate; a Vite build alone is insufficient.
- Vue: invalidate stale asynchronous watcher work and prove that only the current result updates the UI.
- Vue: preserve reactive inputs to composables and dispose manually owned integrations on scope end.
- React: keep render repeatable and update data through its owner rather than mutating shared inputs.
- React: use pure functional updaters when new state depends on pending previous state.
- React: test controlled-input lifetime, error recovery and hydration when the changed surface exercises those contracts.

Keep long-term product care observable: preserve user state during async races, provide
recovery from failures, verify critical journeys in the real production build, and make
every required quality gate cover the file types it claims to cover. Keep fast checks
frequent and full release checks explicit. Existing coverage/complexity thresholds remain
unchanged; this proposal neither installs a competing tool nor lowers an existing gate.

## Limits

This is a repository/install audit, not execution of every prompt workflow in a real
product. No usage history proves a skill unused. No fresh Codex/Claude/Cursor session,
cloud image or real consuming TypeScript/Vue/React application was launched; client discovery
findings separate documented expectations from runtime evidence. External services,
image searches, framework gates in consuming applications, and every external link inside
vendored reference material were not exhaustively exercised. The 47 passing tests prove
their existing installer scenarios, not the seven missing behaviours identified above.
